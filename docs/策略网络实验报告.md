**范围**：ketchup / XHAND 抬升段防滑 **策略网络**（含行为克隆与 PPO），不含检测器单独训练细节

**闭环门闩（PASS）**：extend 抬升 Δz ≥ **6 cm**，且接触步数 ≥ **200**（2 s @ 0.01 s）。

---

## 1. 问题

在 SPIDER ketchup 回放任务中，抓取完成后的 **抬升（extend）** 阶段，物体易因摩擦不足 / 质量增大而滑落。已有：

- **检测网络（NN-1 / NN-2）**：判断是否在滑，并可给出粗糙握力响应；  
- **开环教师搜索**：对部分工况可找到常值 `(grip, Δwrist)` 使抬升 PASS。

但策略侧仍存在三类问题：

1. **检测驱动握力 ≠ 显式策略**：NN-2 在难工况上闭环弱，需要独立的 grip / wrist 策略头。  
2. **训练分布不一致导致不可比**：Policy-1、Policy-2、P2-heavy 各自数据上训出的模型混排，无法归因「算法」还是「数据」。  
3. **开环 BC 到闭环的落差**：如 `friction_div2` 有大量开环 PASS teacher，BC 闭环仍常失败；`friction_s040` 甚至 **搜不到** 常值开环解，纯 BC 无教师可学。

因此需要在 **统一数据与统一考试** 下，系统评估策略网络（BC grip / BC grip+wrist / PPO），并明确部署触发方式（每步动作 vs 检测触发）。

---

## 2. 实验目的

| 编号 | 目的 |
|------|------|
| O1 | 在同一训练集上，比较 **grip-only BC** 与 **grip+wrist BC** 相对检测驱动握力的闭环收益 |
| O2 | 澄清评测口径：只做 **同训算法排名**；跨数据数字仅作 transfer 参考 |
| O3 | 验证短训 **PPO** 能否在完整 `replay_spider_task` 闭环中超过 BC，并区分 `always` / `on_detect` 两种部署模式 |
| O4 | 标定硬边界：哪些工况仍属「无开环教师 / 全方法失败」的 envelope |

**非目标（本报告不覆盖）**：整臂 RL、更换机器人、真实触觉硬件、检测 backbone 从零重训的细节消融。

## 3. 数据方法

### 3.1 任务与观测

- **轨迹**：固定一条 `s01-ketchup_use_01`（arcticv2 / XHAND right）  
- **策略决策段**：抬升 extend，默认 **200 步**  
- **观测**：NN-0 协议 **26 维**滑移/力学/本体特征窗（训练窗长 40；PPO 逐步用当前帧特征 + 少量本体上下文）  
- **动作（Policy-2 / PPO）**：\(g, \Delta r, \Delta p, \Delta y\)，经 `Policy2OpenLoopController` 限速执行；grip 默认上限 0.25  

### 3.2 教师与数据源

| 源 | 策略相关标签 | 用途 |
|----|--------------|------|
| `slip_nn` | `y_grip`（及 `y_event` 供检测） | 检测 + 弱握力监督 |
| `slip_nn_policy` | `y_policy`（min-grip 教师） | Policy-1 / grip BC |
| `slip_nn_policy2` | `y_grip_p2`, `y_wr/y_wp/y_wy` | Policy-2 BC（开环 PASS hits） |
| `slip_nn_policy2_heavy` | 同上（重物 / g-cap） | 重工况 wrist/grip 教师 |

### 3.3 统一集（策略同训用）

`data/slip_nn_unified`：schema GCD 合并上述四源。

1. 缺失 wrist / slip → 0；P2 训练时 **`--mask-zero-wrist`**，避免被 pad 零腕部拉塌  
2. 同 `base_case` **偏好强教师**（policy2/heavy > policy > slip_nn）  
3. 每 `(source, case)` 上限 500；`friction_div2` boost ×3  
4. 分层划分 train / val / test  

**规模（质量过滤后）**：train **7229** / val **901** / test **902**；wrist 教师约占 **39%**。

### 3.4 评测集（策略对比用）

| 套件 | 条数 | 用途 |
|------|------|------|
| 统一闭环表 | 11（A7+B3+C1） | 同训 BC 三类排名；s040 为 envelope |
| PPO 同场表 | 4 | `div2` / `baseline` / `s045` / `s040`，BC vs PPO |

硬 case 教师：`div2` 开环 hits 充足；`s040` 激进搜索 **306 次 0 hits**（常值 P2-A 不可解）。

## 4. 算法设计

### 4.1 总体结构

```
冻结 NN-2 detect backbone
        │
        ├─ grip-only 头  ──► policy_mode=replace   （BC）
        ├─ grip+wrist 头 ──► policy_mode=p2a       （BC）
        └─ PPO 策略（MLP）──► extend hook            （RL）
```

检测 backbone **不参与** PPO 梯度；PPO 直接从特征映射到 4D 动作。

### 4.2 行为克隆策略

| 组件 | 设计 |
|------|------|
| Policy-1 / grip-only | 冻结 detect + MLP → grip；损失：MSE + 稀疏惩罚 |
| Policy-2 | 冻结 detect + MLP → grip + wrist(3)；腕部损失对「无教师窗」掩码 |
| 部署 | soft/hard 滑移门控后 `set_action`，再经限速控制器作用于手指/腕部执行器 |

### 4.3 PPO 策略（小实验）

| 项 | 设定 |
|----|------|
| 训练环境 | `KetchupExtendRLEnv`：缓存轨迹终点后只滚 200 步 extend |
| 算法 | Stable-Baselines3 PPO，80k steps，2 parallel envs |
| Obs | 26 维特征 + grip/wrist/t/μ/m → **33 维** |
| Action | Box[-1,1]^4 → grip∈[0, g_max]，wrist∈[-d_max, d_max] |
| Reward | 接触奖励 + 抬升 shaping + PASS 终奖 − λ·grip − μ·‖wrist‖ |
| 课程 | 偏置 `friction_div2`，少量 `s040`（无开环解，探索用） |

### 4.4 闭环接入（可控）

挂入 `replay_spider_task` 的 `extend_action_hook`，默认 **off**：

| mode | 行为 |
|------|------|
| `always` | 每步查询 PPO（接近训练） |
| `on_detect` | 仅 soft/hard 滑移时查询（接近 BC 部署） |
| `inspect` / `apply_actions=False` | 只记录提议，不改物理 |

`on_detect` 使用 NN-2 **detect-only**，关闭规则 GripBoost 兜底，避免污染对比。

## 5. 试验结果

### 5.1 同训 BC：grip-only vs grip+wrist（相对 NN-2）

数据：`slip_nn_unified`。产物：`data/slip_eval/unified_suite_latest.json`。

| Rank | 策略 | Frontier PASS | 备注 |
|------|------|---------------|------|
| 1 | grip+wrist（BC） | **5/7** | 与 grip 同分，lift margin 略高 |
| 2 | grip-only（BC） | **5/7** | 经济工况平均 grip 更低（0.227 vs 0.248） |
| — | NN-2（非策略头，对照） | **1/7** | 检测驱动握力明显更弱 |

腕部消融（同 seed）：相对 grip-only **helps_pass = 0 / hurts_pass = 0**（无 PASS 翻转）。  
种子方差：grip seed42 vs seed43 frontier 仅约 **3/7** 格一致 → 单次表格噪声大。

**策略侧结论（BC）**：显式策略头显著优于纯检测驱动；在本统一数据与评测表上，**腕部相对纯 grip 的增益不稳定**，不能宣称 P2-A 全面优于 grip-only。

### 5.2 同场闭环：BC vs PPO

产物：`data/slip_eval/ppo_closedloop_vs_bc.json`（均走完整 `replay_spider_task`）。

| 工况 | BC grip | BC wrist | PPO always | PPO on_detect |
|------|---------|----------|------------|---------------|
| friction_div2（μ×0.5） | PASS +8.7 | FAIL −15.8 | **PASS +9.1** | **PASS +8.9** |
| baseline | PASS +7.7 | PASS +8.4 | PASS +8.6 | PASS +8.6 |
| friction_s045（μ×0.45） | FAIL −18.2 | FAIL −22.5 | **PASS +11.9** | FAIL −18.1 |
| friction_s040（μ×0.40） | FAIL −20.0 | FAIL −19.8 | FAIL −19.9 | FAIL −0.6 |

**通关数（/4）**：BC grip **2** · BC wrist **1** · **PPO always 3** · PPO on_detect **2**

补充观察：

- PPO 的 max_grip 约 **0.17–0.18**，低于 BC 的 **0.23–0.25**（握力更省，样本少需多种子确认）。  
- `on_detect` 在 div2 上已能闭环 PASS，但 **s045 的 always 增益未迁移到检测触发模式**（分布 / 时机错位）。  
- **s040**：BC 与 PPO 均 FAIL；与「无开环常值教师」一致，属当前动作空间下的硬边界。

### 5.3 公平性与口径

| 对比 | 可否归因「策略算法」 |
|------|----------------------|
| 同 `slip_nn_unified` 的 grip vs wrist BC | 可以 |
| 跨旧数据域的 P1 vs P2-heavy 混排 | **不可以** |
| Gym-only PPO vs BC 闭环 | 弱可比（考试不同） |
| `replay` 内 PPO always / on_detect vs BC | **可以**（同考试） |

## 6. 未来建议

### 6.1 短周期（稳结论）

1. **多种子（≥3）** 重跑 §5.1 / §5.2，报均值±方差；单次 PASS 表不作最终排名。  
2. 评测 JSON 固化 `threshold` / soft·hard / hook mode，消除「同权重不同天」波动。

### 6.2 中周期（策略性能）

3. **加长 PPO**（≥5e5）并提高 s045 采样；用 Policy-2 BC 做 **actor 热启动**。  
4. 专攻 **always → on_detect 迁移**：检测触发时段 DAgger / 闭环微调，使 s045 增益在部署模式下可复现。  
5. 维持门控接入：默认 off；论文/报告数字必须标明 mode。

### 6.3 长周期（边界与动作空间）

6. **s040**：放弃「再堆常值 BC」；试时变/分段教师或扩展动作；若仍 0 hits，标为 envelope，不进策略排名。  
7. 若业务要求 μ×0.40 必过，单独立项评估是否超出当前 4D P2-A 表达能力。

### 6.4 工程

8. CI：`smoke_extend_hook_step1/2` + 短步数 PPO；策略对比入口固定为  
   `eval_slip_unified_suite.py`（同训 BC）与 `eval_ppo_closedloop_vs_bc.py`（BC vs PPO）。

---

## 7. 总结

策略网络实验表明：

1. **需要显式策略头**：同训下 grip / wrist BC 远强于检测驱动握力。  
2. **腕部不是免费午餐**：统一数据上相对 grip-only 无稳定 PASS 增益。  
3. **短训 PPO 已显示闭环价值**：`always` 模式在 4 格考试上超过 BC（含独过 s045）；更接近部署的 `on_detect` 尚未吃满该增益。  
4. **s040 是方法边界**，不是调参问题。

**下一主线**：多种子稳表 + 把 PPO `always` 的收益迁到 `on_detect`，而不是继续跨数据硬比历史 checkpoint。
